# Dashboard

Static SPA in React 18 + Vite (JavaScript, no router or UI libraries).
CloudFront serves it from the site bucket and forwards `/api/*` to the coordinator,
so the dashboard always talks to the API on the **same origin**: no CORS and
no need to know the EC2 IP.

## Views (hash routing)

| Route | What it shows |
|---|---|
| `#/` | KPIs, balancer alerts, workers per pool (CPU, memory, slots), RabbitMQ queues, cases in progress and a 30-minute load series |
| `#/cases` | Open cases and the 50 most recently finished, status filter |
| `#/cases/{id}` | Barrier (`pending_count`), sub-tasks per file, cancel, consolidated report |
| `#/new` | Case from the dataset, by uploading files (presigned PUT URL) or auto-generated by folder/metadata |
| `#/admin` | Administrators only: Cognito users and their groups (add/remove analyst, supervisor, administrator) |

## Sign-in and roles

Cognito Hosted UI, authorization code + PKCE (public SPA client, no client
secret), implemented in `src/auth/cognito.js` with Web Crypto and no auth
library:

- **Callback**: Cognito redirects to the bare origin (`http://localhost:5173`
  or the CloudFront URL, exactly as registered by Terraform) with
  `?code&state`. `AuthProvider` handles it before any hash route: checks the
  OAuth `state`, redeems the code once with the PKCE verifier and removes the
  query from the address bar.
- **Tokens**: access/ID tokens in memory only; the refresh token in
  `sessionStorage` (this tab, cleared when it closes; never `localStorage`).
  The access token is refreshed 2 minutes before it expires (60 min). Sign
  out revokes the refresh token and goes through Cognito `/logout`.
- **API**: every REST call sends `Authorization: Bearer <access token>` (never
  the ID token). A 401 triggers one refresh and a retry; a second 401 ends the
  session. 403 is shown as a role denial, 0/5xx as "backend unavailable".
- **WebSocket**: `new WebSocket(url, ['bearer', accessToken])`. The
  coordinator closes with 1008 on an invalid/expired token; the dashboard then
  refreshes and reconnects with the new token. Signing out unmounts the live
  state, closing the socket and stopping polling.
- **Roles** come from `GET /api/me` (`cognito:groups`): analyst reads,
  uploads and creates cases; supervisor also cancels; administrator also
  manages roles. Hidden actions are still enforced by the coordinator. A user
  in no group sees "No access". Group changes reach the next token, so the
  user must refresh or sign in again.
- **Reports** are read in two steps: `GET /api/cases/{id}/report` returns a
  presigned URL; the JSON is fetched from S3 without the bearer header. The
  view renders findings, categories, the timeline (evidence time vs
  processing time) and each file's analysis.

Hash routing is used because CloudFront has no route rewriting for the SPA
(see `infra/terraform/modules/storage_frontend`).

## Live state

`src/hooks/useLiveState.jsx` opens `WS /api/ws` and receives `{"type":"state","data":StateResponse}`
(it ignores `{"type":"ping"}`). While the socket is not open it polls
`GET /api/state` every 2 s. It reconnects with backoff 1 s → 2 s → … → 30 s, and if
60 s pass with no message (the ping arrives every 25 s) it treats the socket as dead.

The socket URL is derived from the origin (`https://<cloudfront>` → `wss://<cloudfront>/api/ws`).
It can be forced with `VITE_WS_URL` (see `.env.example`). It carries the
access token as a subprotocol (see Sign-in and roles).

## Development

```bash
cd frontend
pnpm install
cp .env.example .env.local   # choose VITE_PROXY_TARGET and Cognito settings
pnpm dev                  # http://localhost:5173
```

| Variable | Use |
|---|---|
| `VITE_PROXY_TARGET` | `/api` proxy target: `http://localhost:8000` or the CloudFront URL |
| `VITE_S3_BUCKETS` | Buckets proxied under `/__s3/` in dev (AWS hosts only, not MinIO) |
| `VITE_COGNITO_DOMAIN`, `VITE_COGNITO_CLIENT_ID` | Hosted UI domain and SPA client id (`terraform output`). Empty in dev = unauthenticated local mode against a coordinator with an empty issuer and origin secret; a production build without them refuses to run |

`http://localhost:5173` is a registered callback, so `pnpm dev` with the
CloudFront proxy target and the Cognito settings signs in against the real user
pool.

Vite proxies `/api/*` (REST and WebSocket) to `VITE_PROXY_TARGET`:

- `https://<distribution>.cloudfront.net`: a deployed environment; CloudFront adds `X-Origin-Verify` (the domain is in `terraform output`).
- `http://localhost:8000` (default): a coordinator running on the laptop (`uvicorn`). If nothing is
  listening there, the dashboard shows "The Vite proxy could not connect to the coordinator… (ECONNREFUSED)".

The dataset and results buckets only have CORS for the CloudFront domain. To make
file uploads and report reads work from `localhost`, Vite also proxies S3: in
development, `toDevS3Url` (`src/api/client.js`) rewrites
`https://<bucket>.s3.amazonaws.com/...` to `/__s3/<bucket>/...`. The buckets are
configured with `VITE_S3_BUCKETS`.

The PUT URLs signed by the coordinator are SigV2 without `ContentType`, and in SigV2 the
`Content-Type` is part of the signature: that is why `putToS3` sends the file without that header
(with any other value S3 responds `403 SignatureDoesNotMatch`).

## Publish

```bash
pnpm deploy   # build + s3 sync to the frontend bucket + CloudFront invalidation
```

It reads the bucket, distribution and Cognito client settings from `terraform
output` in `infra/`, or from `SITE_BUCKET` / `DISTRIBUTION_ID` /
`VITE_COGNITO_DOMAIN` / `VITE_COGNITO_CLIENT_ID` if they are set. It needs the
AWS CLI with the project profile. CI reads the Cognito settings from the
`COGNITO_DOMAIN` and `COGNITO_CLIENT_ID` repository variables.

Backend contract: `docs/frontend-contract.md`. Verification record: see
"Verification" below.

# Dashboard

Static SPA in React 18 + Vite (JavaScript, no router or UI libraries).
CloudFront serves it from the site bucket and forwards `/api/*` to the coordinator,
so the dashboard always talks to the API on the **same origin**: no CORS and
no need to know the EC2 IP.

## Views (hash routing)

| Route | What it shows |
|---|---|
| `#/` | KPIs, balancer alerts, workers per pool (CPU, memory, slots), SQS queues, cases in progress and a 30-minute load series |
| `#/cases` | Open cases and the 50 most recently finished, status filter |
| `#/cases/{id}` | Barrier (`pending_count`), sub-tasks per file, cancel, consolidated report |
| `#/new` | Case from the dataset, by uploading files (presigned PUT URL) or auto-generated by folder/metadata |

Hash routing is used because CloudFront has no route rewriting for the SPA
(see `infra/terraform/modules/storage_frontend`).

## Live state

`src/hooks/useLiveState.jsx` opens `WS /api/ws` and receives `{"type":"state","data":StateResponse}`
(it ignores `{"type":"ping"}`). While the socket is not open it polls
`GET /api/state` every 2 s. It reconnects with backoff 1 s → 2 s → … → 30 s, and if
60 s pass with no message (the ping arrives every 25 s) it treats the socket as dead.

The socket URL is derived from the origin (`https://<cloudfront>` → `wss://<cloudfront>/api/ws`).
It can be forced with `VITE_WS_URL` (see `.env.example`).

## Development

```bash
cd frontend
npm install
cp .env.example .env.local   # choose VITE_PROXY_TARGET
npm run dev                  # http://localhost:5173
```

Vite proxies `/api/*` (REST and WebSocket) to `VITE_PROXY_TARGET`:

- `https://<distribution>.cloudfront.net`: a deployed environment; CloudFront adds `X-Origin-Verify` (the domain is in `terraform output`).
- `http://localhost:8000` (default): a coordinator running on the laptop (`uvicorn`). If nothing is
  listening there, the dashboard shows "The Vite proxy could not connect to the coordinator… (ECONNREFUSED)".

The dataset and results buckets only have CORS for the CloudFront domain. To make
file uploads and report reads work from `localhost`, Vite also proxies S3: in
development, `toDevS3Url` (`src/api/client.js`) rewrites
`https://<bucket>.s3.amazonaws.com/...` to `/__s3/<bucket>/...`. The buckets are
configured with `VITE_S3_BUCKETS`.

The PUT URLs signed by the coordinator are SigV2 without `ContentType`, and in SigV2 the
`Content-Type` is part of the signature: that is why `putToS3` sends the file without that header
(with any other value S3 responds `403 SignatureDoesNotMatch`).

## Publish

```bash
npm run deploy   # build + s3 sync to the frontend bucket + CloudFront invalidation
```

It reads the bucket and distribution from `terraform output` in `infra/`, or from
`SITE_BUCKET` / `DISTRIBUTION_ID` if they are set. It needs the AWS CLI with the
project profile.

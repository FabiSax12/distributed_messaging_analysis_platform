# Dataset

Owner: Camila Hidalgo (support: David Molina). Only synthetic data or public data
with a license that allows this use. Every source is recorded in the
provenance table below.

## Minimum requirements

| Item | Minimum | Notes |
|---|---|---|
| Cases | 40 | One `manifest.json` per case |
| Heterogeneous cases | >= 10 | Text + image + audio + (video or document) in the same case (`heterogeneous: true`) |
| Text messages | 20,000 | Realistic WhatsApp or Telegram export format, with timestamps and senders (formats below) |
| Images | 300 | Known positive ratio (how many contain sensitive content), recorded in the ground truth |
| Voice notes | 150 | Varied durations (a few seconds to several minutes) |
| Heavy cases | >= 5 | With video or attachments of >= 200 MB (M3 throughput and chunking) |
| Ground truth | At least a labeled sample | Enough to compute precision/recall per category |
| Provenance | Every source | Origin, license and whether it was AI-generated |

Setup (once, from the repo root): `uv sync --all-packages --group dataset`.
Then `uv run --group dataset python dataset/generators/validate_manifests.py` prints
counts (cases, heterogeneous cases, heavy cases, sources per content type,
labeled sources) to compare against this table.

## Repository layout

```
dataset/
  generators/                 scripts that produce cases (plus validate_manifests.py)
  schema/
    case_manifest.schema.json
    ground_truth.schema.json
  cases/<case_id>/
    manifest.json             committed
    chat/whatsapp.txt         committed if small (text exports)
    chat/result.json          committed if small (Telegram export)
    media/...                 NOT committed (images, audio, video, documents)
  ground_truth/<case_id>.json committed
  tests/                      tests of the validator
```

- `case_id` is lowercase, e.g. `case-001`, and equals its directory name.
- Source paths in the manifest are relative to the case directory.
- Raw media is never committed. `dataset/.gitignore` ignores image, audio,
  video, document and archive extensions (any letter case) and any `large/` or
  `build/` folder. Put a text export that is too big for git (more than a few
  MB) under `cases/<case_id>/large/`.
- Media goes to the dataset S3 bucket under `cases/<case_id>/<path>`, so an
  object key is `cases/<case_id>/` + the manifest path. The upload script
  `scripts/dataset/upload-dataset.sh` still uses the Project I approach
  (copies one folder 30 times as `batch-01/` to `batch-30/` plus a top-level
  `manifest.json`) and will be adapted to this layout.

## Case manifest

Schema: `dataset/schema/case_manifest.schema.json`. Enum values match
`services/shared/shared/analysis.py` (`CasePriority`, `ContentType`).

```json
{
  "case_id": "case-001",
  "title": "Synthetic extortion chat with voice notes",
  "priority": "high",
  "heterogeneous": true,
  "sources": [
    {"path": "chat/whatsapp.txt", "content_type": "text", "chat_format": "whatsapp",
     "timezone": "America/Costa_Rica", "sha256": "<64 hex>", "size_bytes": 48211},
    {"path": "media/IMG-20240301-WA0001.jpg", "content_type": "image", "sha256": "<64 hex>", "size_bytes": 183004},
    {"path": "media/PTT-20240301-WA0002.opus", "content_type": "audio", "sha256": "<64 hex>", "size_bytes": 25120},
    {"path": "media/VID-20240302-WA0003.mp4", "content_type": "video", "sha256": "<64 hex>", "size_bytes": 231000000}
  ],
  "notes": "Generated by generators/<script>.py, seed 42"
}
```

| Field | Required | Meaning |
|---|---|---|
| `case_id` | yes | Matches the directory name |
| `title` | yes | Short description |
| `priority` | yes | `low`, `medium`, `high`, `critical` (input for M2) |
| `heterogeneous` | yes | Must be `true` exactly when sources include text, image, audio and video or document (the validator checks it) |
| `sources[].path` | yes | Relative path, no leading `/`, no `..` |
| `sources[].content_type` | yes | `text`, `image`, `audio`, `video`, `document` |
| `sources[].sha256` | yes | Lowercase hex SHA-256 of the file (also the key for M3 dedup) |
| `sources[].size_bytes` | yes | File size |
| `sources[].chat_format` | no | `whatsapp` or `telegram`; only for text chat exports |
| `sources[].timezone` | no | IANA zone of the export's naive timestamps; default `America/Costa_Rica` |
| `notes` | no | Free text (generator, seed, origin) |

## Ground truth

Schema: `dataset/schema/ground_truth.schema.json`, one file per labeled case in
`dataset/ground_truth/<case_id>.json`. Category and severity values match
`FindingCategory` and `Severity` in `shared/analysis.py`; locators use the same
field names as `Evidence`, so predicted and expected findings can be matched
for precision/recall.

- A listed source with `"findings": []` is a known negative; a source that is
  not listed is unlabeled (excluded from the metrics).
- `kind` is `message` (needs `message_index`), `audio_segment` (needs
  `audio_start_s` and `audio_end_s`), `image` (optional normalized `bbox`;
  omitted = whole image) or `document` (no locator). A finding cannot carry the
  locators of another kind. These are the same rules `Evidence` enforces in
  `shared/analysis.py`. `x + w` and `y + h` may exceed 1 by at most `1e-6`
  (`BBOX_TOLERANCE`, the same in both places).
- Source paths follow the same safe-path rule as the manifest.
- `message_index` is the 0-based position of the message in the export, as
  defined below.

```json
{
  "case_id": "case-001",
  "labeled_by": "Camila Hidalgo",
  "sources": [
    {"path": "chat/whatsapp.txt", "findings": [
      {"category": "threat", "severity": "high", "kind": "message", "message_index": 2}
    ]},
    {"path": "media/IMG-20240301-WA0001.jpg", "findings": [
      {"category": "sensitive_image", "severity": "medium", "kind": "image",
       "bbox": {"x": 0.12, "y": 0.30, "w": 0.40, "h": 0.25}}
    ]},
    {"path": "media/PTT-20240301-WA0002.opus", "findings": [
      {"category": "offensive_language", "severity": "low", "kind": "audio_segment",
       "audio_start_s": 3.5, "audio_end_s": 6.0}
    ]},
    {"path": "media/VID-20240302-WA0003.mp4", "findings": []}
  ]
}
```

## Chat export formats

### WhatsApp (`chat_format: "whatsapp"`)

Plain UTF-8 text file, Android export style, one message per entry:

```
DD/MM/YY, HH:MM - Sender: message
```

- Date `DD/MM/YY`, 24-hour time `HH:MM`, then ` - ` (space, hyphen, space).
- `Sender` is the display name up to the first `: `. Entries without a sender
  (`DD/MM/YY, HH:MM - <text>`) are system messages (group created, number
  changed, encryption notice).
- Multi-line messages: any line that does not start with the
  `DD/MM/YY, HH:MM - ` prefix continues the previous message.
- Media exported without files appears as `<Media omitted>`. When the media
  is part of the case, the line names the file instead:
  `IMG-20240301-WA0001.jpg (file attached)`, and that file is a source of the
  same case under `media/`.
- Timestamps are naive local time; the parser attaches the source `timezone`.
- `message_index` counts every entry with the date prefix (system messages
  included), starting at 0, in file order.

```
01/03/24, 21:14 - Alex Placeholder: are you coming tomorrow?
01/03/24, 21:15 - Sam Sample: <Media omitted>
01/03/24, 21:16 - Alex Placeholder: if you tell anyone,
you will regret it
```

(The third message spans two lines; its `message_index` is 2.)

### Telegram (`chat_format: "telegram"`)

The `result.json` produced by Telegram Desktop's "Export chat history" (JSON):

```json
{
  "name": "Test Group",
  "type": "private_group",
  "id": 1000001,
  "messages": [
    {"id": 1, "type": "message", "date": "2024-03-01T21:14:00", "from": "Alex Placeholder", "from_id": "user1001", "text": "are you coming tomorrow?"},
    {"id": 2, "type": "message", "date": "2024-03-01T21:15:00", "from": "Sam Sample", "from_id": "user1002", "text": "", "media_type": "voice_message", "file": "voice_messages/audio_1@01-03-2024_21-15-00.ogg", "duration_seconds": 12},
    {"id": 3, "type": "message", "date": "2024-03-01T21:16:00", "from": "Alex Placeholder", "from_id": "user1001", "text": ["if you tell anyone, ", {"type": "bold", "text": "you will regret it"}]}
  ]
}
```

- Required per message: `id`, `type` (`message` or `service`), `date` (naive
  ISO 8601 local time; the parser attaches the source `timezone`), `from`
  (sender display name; absent on some `service` entries) and `text`.
- `text` is either a string or a list mixing strings and entity objects
  (`{"type": ..., "text": ...}`); the plain text is their concatenation.
- Media messages add `photo` or `file` (path relative to the export) and, for
  voice notes, `media_type: "voice_message"` and `duration_seconds`.
- `message_index` is the 0-based position in `messages[]` (not `id`).

## Generating the dataset

Everything comes from scripts in `dataset/generators/` with seed 42. Needs
`ffmpeg`/`ffprobe` on PATH and a TTS backend (Windows SAPI, or `espeak-ng`
elsewhere; see `tts.py`).

```sh
uv sync --all-packages --all-extras --group dataset
uv run --group dataset python dataset/generators/fetch_coco.py        # ~241 MB annotations + 310 images (51 MB) into dataset/build/coco
uv run --group dataset python dataset/generators/generate_dataset.py  # ~5 min; 1.6 GB of media under dataset/cases
uv run --group dataset python dataset/generators/validate_manifests.py --verify-files
uv run --all-packages --all-extras --group dataset python dataset/generators/dataset_stats.py
```

| Script | What it does |
|---|---|
| `fetch_coco.py` | Picks COCO val2017 images with a redistributable license: all 73 with a knife/scissors box, plus seeded negatives. Writes `data/coco_selection.json` (committed: id, license, Flickr URL, normalized boxes) |
| `corpus.py` | Phrase banks: benign chat (es/en), harmful phrasings the rules know, paraphrases they miss, hard negatives, voice-note sentences |
| `tts.py` | Synthesizes voice-note sentences (16 kHz mono WAV) |
| `generate_dataset.py` | Plans the 40 cases from one RNG, renders chats, voice notes (Opus), videos (H.264 + AAC), copies images, writes manifests and ground truth |
| `validate_manifests.py` | Schema and semantic checks; `--verify-files` hashes local media |
| `dataset_stats.py` | Independent count: parses chats with the text worker's own parser, ffprobes every audio/video, opens every image |
| `evaluate.py` | Runs the production ops on labeled sources and computes precision/recall (see Evaluation) |

The plan (texts, labels, message indexes, segment times) is deterministic.
Media bytes depend on the TTS voices and the ffmpeg/x264 build, so a rebuild on
another machine produces equivalent but not byte-identical media (the
manifests then fail `--verify-files` until regenerated with the new hashes).
The published media is the reference copy: `scripts/dataset/upload-dataset.sh
<bucket>` publishes `dataset/cases/<case_id>/<path>`, and
`scripts/dataset/download-dataset.sh <bucket>` fetches it back and verifies the
hashes. Terraform has no dedicated dataset bucket, so the reference copy lives in
the evidence bucket under `dataset/`: published on 2026-11-11 to
`s3://msg-analysis-dev-evidence-114823617609/dataset/cases/` (545 sources and
manifests, 1,715,238,653 bytes, identical to the manifests) and
`.../dataset/ground_truth/`. Uploading needs `s3:PutObject` on that prefix and
`kms:GenerateDataKey` on the evidence bucket key.

Case kinds: 001-010 heterogeneous (text, 8 images, 5 voice notes, small video);
011-015 heavy heterogeneous (text, 6 images, 3 voice notes, 264-409 MB video);
016-035 standard (text, 8-9 images, 4-5 voice notes); 036-038 text only
(large chats); 039-040 text and 12 images. 28 cases use a harmful scenario

sports). No case includes documents: documents have no analysis operation yet.

Ground truth contents: 635 harmful messages (301 threat, 156
offensive_language, 101 violence, 77 illicit_activity), 43 harmful audio
segments, 134 image boxes. Known negatives: 227 images, 110 voice notes, 12
videos and the 12 benign chats (every chat line not listed is negative).

How labels were produced:

- **Text and audio**: the generator records the category of every harmful
  message or spoken sentence it inserts, by meaning. About 70% of harmful chat
  messages use a phrasing the rules know; the rest are paraphrases with no
  rule keyword (expected false negatives). About 0.6% of messages are hard
  negatives: harmless lines containing a rule keyword ("the photo shoot is at
  3", "I'm going to kill you at chess tonight haha"), expected false
  positives. Audio segments are the exact start/end of the synthesized
  sentence within the note.
- **Images**: COCO's human-annotated knife and scissors boxes, normalized.
  This measures exactly what the image worker claims to do (flag knives and
  scissors for human review). Most COCO knives are cutlery: a match means "a
  knife is visible", not "the image is harmful". The worker is not a general
  harmful-image classifier and the evaluation does not pretend otherwise.

## Evaluation

`evaluate.py` runs `text_analyze`, `image_analyze` and `audio_analyze` (video
included) on every labeled source with the production code, in-process via
`workers.ops.run_local.run` (no broker, no S3), and compares predictions with
the ground truth. Matching is one-to-one, per category, within one source:

- message: same category and same `message_index`;
- audio segment: same category and the predicted segment overlaps the labeled
  one, with 0.5 s slack each side (Whisper merges and splits sentences);
- image: same category and box IoU >= 0.5; plus an image-level score (any
  finding vs any label).

Results are in [Dataset evaluation results](#dataset-evaluation-results).

## Dataset evaluation results

Run on 2026-11-11 with `evaluate.py` over all 505 labeled sources (40 chats,
300 images, 150 voice notes, 15 videos) on the production operations: text
rules `bilingual-rules` v1, YOLOv8n COCO (conf 0.25), faster-whisper tiny int8
(2 threads, beam 1, language auto). 0 operation errors. Raw numbers:
`dataset/evaluation/metrics.json` and `metrics.md`.

| Category | Modality | TP | FP | FN | Precision | Recall | F1 |
|---|---|---|---|---|---|---|---|
| threat | text | 207 | 23 | 94 | 0.900 | 0.688 | 0.780 |
| threat | audio + video | 14 | 6 | 6 | 0.700 | 0.700 | 0.700 |
| offensive_language | text | 113 | 30 | 43 | 0.790 | 0.724 | 0.756 |
| offensive_language | audio | 10 | 0 | 0 | 1.000 | 1.000 | 1.000 |
| violence | text | 64 | 37 | 37 | 0.634 | 0.634 | 0.634 |
| violence | audio | 7 | 0 | 0 | 1.000 | 1.000 | 1.000 |
| illicit_activity | text | 46 | 32 | 31 | 0.590 | 0.597 | 0.594 |
| illicit_activity | audio + video | 5 | 0 | 1 | 1.000 | 0.833 | 0.909 |
| sensitive_image (box, IoU >= 0.5) | image | 23 | 10 | 111 | 0.697 | 0.172 | 0.275 |
| sensitive_image (image level) | image | 27 | 1 | 46 | 0.964 | 0.370 | 0.535 |

Mean IoU of matched boxes: 0.84.

Interpretation:

- **Text rules** miss every paraphrase by construction (about 30% of harmful
  messages): "sé dónde vivís", "money laundering" (only the Spanish "lavado de
  dinero" is a rule) and "we'll jump him" have no keyword. Every false
  positive comes from the hard negatives: "documental sobre lavado de dinero"
  (21), "qué idiota yo jaja" (20), "golpear la bola" (18), "golpiza del boxeo"
  (14), "kill you at chess" (14), "drug deal investigation" (11), "stupid
  printer" (10), "won't hurt you" (9). Keyword rules cannot read context:
  they are review cues, as the worker docstring says.
- **Audio**: Whisper tiny transcribes the synthetic English voices almost
  verbatim, so audio inherits the rules' behavior on a smaller sample (43
  labeled segments). The 6 audio threat false positives are the spoken
  "kill you at chess" hard negative; the misses are spoken paraphrases.
  Synthetic TTS speech is cleaner than real voice notes (no noise, accents
  or overlapping speakers), so these audio numbers are an upper bound.
- **Images**: YOLOv8n finds 37% of the images that contain a knife or
  scissors and is almost never wrong when it flags one (1 image-level FP in
  227 negatives), but it misses most boxes: COCO knives are mostly small
  cutlery on dining tables, and nano-sized YOLO at 640 px rarely detects
  objects of a few hundred pixels. The worker detects objects; it does not
  judge whether an image is harmful.
- Severity is not scored: the rules assign one fixed severity per category,
  equal to the ground truth's, so it would add no information.
